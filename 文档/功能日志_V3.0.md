## 六、V3.0 修订（MDF/LDF 直连与交互收口）

本节记录 2026-11-06 在 V3.0 基线之上追加的功能与修复，最终交付以本节为准。

### 1. MDF / LDF 直接附加

新增 5 个引擎函数（`kpsc_to_cmsg.py`，位于 `list_databases()` 之后）：

| 函数 | 作用 |
|---|---|
| `_norm_file_path` | 统一 `abspath + normpath + normcase`，用于物理路径比对 |
| `_sql_literal` | T-SQL 字面量单引号转义 |
| `_sql_ident` | 标识符 `]` → `]]` |
| `find_attached_database` | 连 `master` 读 `sys.databases` + `sys.master_files`（`file_id=1`），按物理路径识别已附加库 |
| `attach_database_file` | 校验文件、识别已附加、上线 OFFLINE 库、执行 `FOR ATTACH` 或 `FOR ATTACH_REBUILD_LOG`、返回库名/状态 |

处理规则：

1. MDF 必须存在、后缀 `.mdf`、非空。
2. LDF 可选；未选时自动探测同目录同名 `.ldf`；仍没有则走 `ATTACH_REBUILD_LOG`。
3. 已附加：按物理路径命中，返回 `action="existing"`，不重复 ATTACH；状态非 `ONLINE` 时执行 `ALTER DATABASE … SET ONLINE` 并复查。
4. 未附加：有 LDF → `CREATE DATABASE … ON (FILENAME=mdf),(FILENAME=ldf) FOR ATTACH`；无 LDF → `FOR ATTACH_REBUILD_LOG`。
5. 库名取 `db_name` 或 MDF 基名，清 `[]` 与控制字符，最长 100。
6. 实例已有同名库但不是该 MDF：直接中文报错，不覆盖、不自动加后缀。
7. `pyodbc.Error` 统一转中文提示，覆盖服务账户权限、文件被占用、MDF/LDF 不配套三类常见原因。

实测：

- 有日志分支 `_工作区\test_attach.py`：临时库 → `sp_detach_db` → `attach_database_file` 返回 `action=attached / state=ONLINE / log_rebuilt=False` → 建表插值 `probe rows 1` → DROP → 文件 `cleanup False False`。
- 仅 MDF 分支 `_工作区\test_attach_nolog2.py`：目录 `C:\ProgramData\kpsc_attach_nolog_test`（先 `icacls /grant '*S-1-1-0:(OI)(CI)M'`），建库 → 写入 → detach → 删除 LDF → `attach_database_file(SRV, mdf, "", …)` 返回 `action=attached / state=ONLINE / log_rebuilt=True` → `probe rows 1` → DROP → `cleanup False False`。SQL Server 重建的 LDF 随 DROP 一并删除，测试目录已清空并移除。
- 真实文件识别：`D:\kspcV81\BZ\server\workData\kspcDefault.mdf` → `kspcDefault / ONLINE`；`F:\GraspServer\CMSQ\Data\财贸测试demo.mdf` → `财贸测试demo / ONLINE`。

边界：附加只改变实例挂载关系，不修改账套内容；不做只读附加，不自动备份已附加库，不自动触发直导。

### 3. GUI 线程安全修复

真问题不是单纯 `after`：

- 工作线程直接读 `tkinter.StringVar`，触发 `RuntimeError: main thread is not in main loop`（堆栈 `precheck → _conn → _params → globalgetvar`）。
- 修法一：新增 `self.ui_q` + `_ui(fn)`，把全部 16 处 `self.root.after(0, …)` 改为 `_ui(…)`；`_drain()` 在主线程排空队列并执行，异常写日志。
- 修法二：新增 `self._param_cache`，对 8 个连接变量 `trace_add("write", self._sync_params)`；`_params(side)` 在主线程先同步再返回，在工作线程只读缓存。
- 修法三：把工作线程内的 tkinter 变量读取全部提前到主线程（`options`、`backup`、`cache_after`、`include_join`、`srv/db`、`path` 等）。
- `_work()` 异常分支追加 `traceback.format_exc()` 到日志，便于定位。

### 4. 结存严格核对口径修复

首次 GUI 全链路冒烟出现“严格核对 199 项 / 不符 4”，复核为 225 项 / 不符 3，全部落在结存 Qty 与 Total：

- 期望 100 / 100000，实际 90 / 90000。
- 根因：`strict_verify` 的结存部分错误复用了期初 `plan["stock_rows"]`（源 `t_prime_goodsstock` 是 100），而源库期初 100、当前结存 90 本来就是两个口径。
- 修法：结存部分独立遍历 `plan["src"]["cur_stock"]`（源 `t_base_goodsstock`），按 `(pid,kid)` 去重后比对 `GoodsStocks.Qty`、`GoodsStockscost.Qty/Price/Total/Period`。
- 修后：`VERIFY 32/32`、`STRICT total 225 / bad 0`。
