## 1. 编号规则（决定软件里能不能显示）

财贸与辉煌一致：客户端树按**编号前缀**构建，父编号 = 子编号去掉末 5 位。

| 规则 | 说明 |
|---|---|
| 纯数字 | 编号含字母 → 列表行不渲染 |
| 长度 | ≥5 且为 5 的倍数；3 位编号会触发 `flPtypeid` 解析错误 |
| 级联 | 一级 `00001` 起；二级 = 父编号 + 5 位行序（`0000100001`） |
| 同值 | `typeId` 与 `UserCode` 写同一个新编号 |
| 原位 | 原编号写入 `Comment`：`竞驰导入|原编号:001|原ID:1` |

### 为什么价格必须写 `T_Jxc_PtypeUnit`

财贸的 `T_Jxc_PtypeUnit`（23 列）被 135 个存储过程/函数引用，`p_jxc_GetPtypePrice`、
`P_Base_SavePtypeUnit` 都直接读写它，是价格/单位的**主载体**。
`xw_P_PtypePrice`、`xw_PtypeUnit` 在财贸仅 3~5 个 `xw_` 过程引用，属兼容表。
因此本工具主写 `T_Jxc_PtypeUnit`，兼容表默认不写（可勾选）。

每个商品（含分类行）至少写一条 `nUnit=1` 的记录，否则单据取不到单位。

## 10. 刷新与显示机制

| 项目 | 财贸做法 | 辉煌做法（勿套用） |
|---|---|---|
| 增量标记 | `XW_BaseUpdateTag(BaseType,UpdateTag)` → 全部 `0` | `xw_BaseUpdateTag=0` |
| 行标记 | 五张基础表 `UpdateTag=10000` | `updatetag=10000` |
| 客户端读取 | `xw_GetBasicData(@cMode,@nUpdateTag,@nUsePage,@Rec,@OutRecords OUTPUT)` | 5 参数含 `@EtypeID` |
| 模式 | `B/C/V/P/K/E/D`（C=客户、V=供应商） | `B/P/K/E/D/A` |
| 缓存 | `F:\GraspServer\CMSQ\Data\BaseInfo\<账套>` | `Data\localData\<账套>-00000-*` |

`xw_GetBasicData` 的 `B` 返回全部往来单位，`C` 仅 `isclient=1`，`V` 仅 `isclient=0`。
因此 `isclient` 判错会导致“客户/供应商界面看不到”，工具把它列为校验项。
