## 二、从目录中得到的新证据

### 2.1 财贸客户端缓存是 SQLite，可做 UI 层核对

`BaseInfo\财贸测试demo\7269A748-9639-4909-9D9D-0436FDE98133` 的表清单与行数：

| 缓存表 | 行数 | 关键列 |
|---|---:|---|
| `B` | 7 | `BTYPEID/BFULLNAME/BNAME/BCOMMENT/bIsClient/Comment1..8` |
| `P` | 3 | `Ptypeid/PFULLNAME/UNIT1/Unit2/Unit3/ShelfLife/UnitRate1/UnitRate2/RetailPrice/DefaultStock/pCostModeName/pBrandTypeID/PCOMMENT1..8` |
| `K` | 7 | `ktypeid/KFULLNAME/KUSERCODE/bPosition/bKIsStop` |
| `E` | 4 | `ETYPEID/EFULLNAME/BIRTHDAY/DEPARTMENT/eaccount` |
| `D` | 3 | `DTYPEID/DFULLNAME/DNAMPY` |
| `A` | 266 | `atypeid/AFULLNAME/AUSERCODE` |
| `BaseUpdateTag` | 32 | `BaseInfo/UpdateTag` |

当前 `B` 只有 7 行，数据库 `Btype` 已有 8 行（含新增 `00006 测试单位`），**缓存缺这一行**。这说明：数据库写入成功不等于客户端已刷新；清缓存并重开账套后，客户端才会重建 `BaseInfo`。

### 2.2 辉煌缓存是每表一个文本文件，清理必须按账套前缀

`HH15new-00000-B` 首行是库名、第 2 行是 GUID、末行 `$$BaseInfoEnd$$`；现有工具只删除 `root` 下 `db-` 开头且含 `-00000-` 的文件，不会误删其他账套。但辉煌实际缓存前缀是 `HH15new`，用户登录库名可能不同；需要“账套名 ↔ 缓存前缀”的映射提示。

### 2.3 竞驰目录没有可用的 DSN/连接配置

`XDevCore.ini` 只有设备型号，`kspcCore.dll` 仅 267 B；因此工具不能从客户端目录推断数据库地址，必须由用户手工输入服务器与库名。这与本轮“数据库参数不预设”的改造一致。

### 2.4 `Base.Ini` 是显示配置，不是数据口径

辉煌 `Base.Ini` 定义各基本资料页签的列宽与隐藏列（`Typeid/Sonnum/UnitRate1/CostMode/PrePrice1..4/RecPrice/BarCode/NAMEPY/Ucode`），可用于解释“字段已写入但界面看不到”的显示问题，不应作为导入字段依据。

## 三、功能补全建议（按优先级）

### P0：直接影响“导入后用户能看到正确数据”

1. **客户端缓存核对（建议下一版实现）**
   - 新增“缓存核对”按钮：读 `BaseInfo\<账套>\<GUID>` SQLite 的 `B/P/K/E/D` 行数与编号，和目标库 `Btype/ptype/Stock/Employee/Department` 比对；
   - 输出缺失编号清单，提示“缓存为导入前快照，请清缓存并重开账套”；
   - 辉煌侧按 `localData\<前缀>-00000-*` 解析首行/行数，给同样的提示；
   - 这样可把“数据库校验通过”延伸到“客户端 UI 可读到”。

2. **导入前模板预检闸门**
   - 在“一键直导”前增加 27 列模板对照：字段落位、必填列、单位换算率、条码、父项编号；
   - 发现“有悖模板”的项时阻断导入，提供“仅预览差异 / 以模板为准修正”两段式；
   - 修正前强制生成 `.bak` 备份，并在结果页显示备份路径与校验和。

3. **备份/回滚向导**
   - 扫描 `BackUp` 目录，列出 `.bak` 的文件名、大小、时间、数据库逻辑名；
   - 回滚前校验备份头与目标库名，一键 `RESTORE ... WITH MOVE`；
   - 回滚后自动重跑 32 项常规校验与 247 项逐字段校验。

4. **完整模板覆盖**
   - 当前 27 列之外的 `ShelfLife`（源 `bzDateNum=150` 未写入，库内为 0）、`serialType→bBlockNo`、四级/五级批发价列位；
   - 在字典与核对报告中明确标注“模板未列但源有值”的字段，避免用户误以为漏导。

### P1：可维护性与防错

5. **结构化日志**：运行日志同时写 JSONL（时间、级别、模块、SQL、影响行数、耗时），并提供 HTML 汇总报告，便于以后复盘。
6. **内置隔离库自检**：辉煌侧提供“创建隔离副本 → 导入 → 校验 → 删除”的一键自检，避免直接写生产库。
7. **账套名 ↔ 缓存目录/前缀映射**：财贸 `BaseInfo` 子目录名是账套名，可能与登录库名不一致；清理前先做映射确认，清理前把原缓存移到 `_cachebak_时间戳`，不要直接删除。
8. **缓存新鲜度标记**：导入完成后记录 `BaseInfo` 文件时间与行数；若客户端未重开，结果页明确显示“缓存仍为旧快照”，不把 UI 显示问题误报为数据缺陷。

### P2：界面与交付体验

9. 统一主题色与控件圆角；左侧模块导航 + 右侧详情，减少五个页签来回切换。
10. 校验结果表增加差异行高亮、“仅看差异”开关、CSV/HTML 导出。
11. 应用图标、关于对话框、日志一键打开目录、预检失败时置灰“开始直导”。
12. 目标卡显示“参考库”而非“默认库”，并在切换目标时保留用户已填连接参数（本轮已完成）。
