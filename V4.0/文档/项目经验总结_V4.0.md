# 项目经验总结 V4.0：竞驰 → 管家婆双版本

> 这份总结只记录**已经在本机真实库上跑过**的事实；未验证的推断不写进来。
> 配套：`数据搬移验证记录_V4.0.md`、`数据字典_竞驰到双版本_V4.0.md`、`核心字段映射真实核对_V4.0.csv`。

## 一、两条链路为什么能合成一个工具

| 维度 | 财贸双全 | 辉煌 TOP15 | 融合做法 |
|---|---|---|---|
| 入口 | 竞驰 `kspcDefault` | 同一源库 | GUI 只连一次源，目标二选一 |
| 写入方式 | 直写目标表（带事务/逐行） | 官方存储过程 `p_hh_*` | 引擎层抽象“模块 → 写入函数”，GUI 只调统一 `run_import` |
| 编号 | 目标自定义，需数字化/级联 | 官方过程**会改写**编号并返回真实树号 | 明细引用统一取 `OUTPUT g_tree/u_tree`，不自行映射 |
| 单位 | `T_Jxc_PtypeUnit` 矩阵（`nUnit`） | `xw_PtypeUnit` + `xw_P_PtypePrice` | 同一源行拆成两套“单位/价格”写入器 |
| 期初 | 必须先关账/按目标规则写 | 需临时 `sysdata.iniover=0` | 适配器内 `try/finally` 恢复，GUI 不需要知道 |
| 校验 | 32 项 + 225 严格项 | 14 项 + 114 字段项 | 统一三元组 `(项目, 结果, 明细)`，同一张结果表展示 |
| 回滚 | 整库 `.bak` | 整库 `.bak` + DROP/RESTORE 隔离副本 | GUI 备份入口同一套；测试在副本上做 |

## 三、踩过的真坑（均已修，勿重复）

1. **`rc=-1124` 不只“编号重复”**：编号与名称任一重复都会报；必须两套唯一化都做。当前策略：编号冲突续排，名称冲突加 `(竞驰)`。
2. **官方过程会改写自定义编号**：`001→00102`、`00101→0010101`、`1→101`、`0000600001→0000101`；明细表只能引用 `OUTPUT g_tree/u_tree`，自己算映射必错。
3. **隔离库删行回不到基线**：编号续排会留下空洞；唯一正确恢复是 `DROP + RESTORE`。还原时逻辑名取备份头（`HH91Full_Data/HH91Full_Log`），`WITH MOVE` 才能落到新路径。
4. **`call_unit` 的 `@Bank` 与 `@BankAccounts` 是两个参数**：只传后者会导致银行账号空。修法：两参数同传源 `bankcount`。
5. **`p_hh_BasicInsertE_Commodity` 没有 `@name`**：`ename` 只能插入后 `UPDATE` 补写；不要试图加参数。
6. **辅助单位换算率取错列**：竞驰 `unitrelation` 多为 1（基本比例），`unitrelation2` 才是辅助换算率（本例 100）。优先取 `unitrelation2`。
7. **条码 `UnitID` 必须是数字串**：写单位名文本会让读者链路 `fn_GetBarCodeStr` 报 245/22018，整块商品列表崩溃。
8. **同一 MDF 已被实例 A 附加，实例 B 再 ATTACH 必报错误 32**；跨服务账户读别人目录必报错误 5。这不是代码 bug，是实例/账户边界。
9. **LDF 命名有两种**：SQL Server 默认 `<库>_log.ldf`，部分工具生成 `<库>.ldf`；GUI 必须双候选探测。
10. **tkinter 的 `pack` 与 `grid` 不能在同一父容器混用**：卡片标题要放独立 header 帧，body 只做 grid。
11. **`_defaults()` 必须先建全所有 `StringVar`**：否则 `_build()` 任一 `self.var["x"]` 都会 `KeyError`。
12. **PyInstaller 三件套**：`--hidden-import tkinter --hidden-import _tkinter` + `--add-data Lib\tcl8.6;lib\tcl8.6` + `Lib\tk8.6`，且 tcl/tk 版本要与 DLL 完全一致。

## 四、可复用的方法论

### 4.1 字典必须“写完再核”

不要用设计稿当字典。正确顺序：
1. 从源库 `sys.columns` 取 104 表 / 1626 字段；
2. 生成映射，逐条到目标库 `sys.columns` 校验，找不到就标“目标缺列”；
3. 真实导入一批源行；
4. 按备注 `竞驰ID:n`（或 `原ID:n`）把目标行与源行配对，逐字段回读；
5. 只有回读通过，才把字典定稿。

本轮就是第 2 步抓出 `YRTotal00/YPTotal00` 不是财贸列，修正为 `PreARTotal00/PreAPTotal00`，才做到“目标缺列 = 0”。

### 4.2 校验要分“真缺陷”和“口径”

- 拼音列目标存小写：两侧统一 `upper()` 再比，不是缺陷；
- `ptype.punitname` 官方过程写成 `1件=1个` 组合串：改“单位名包含关系”核对；
- `busercode/pusercode/kusercode/eusercode` 目标会因同号/重名续排：作为“技术编号”单列记录实际值，不计业务字段不符。

把口径问题当成缺陷会无限返工；把缺陷当成口径会漏数据。判别标准是：**源值在目标有没有业务等价物**。

### 4.3 写库必须可回滚

- 每次导入前整库 `.bak`（`COPY_ONLY` 用于测试副本）；
- 失败不删行“修”，直接 DROP + 还原；
- 目标表已有真实数据时，绝不用“清空重导”作为默认策略。

## 五、工程师视角的功能补强（已融合 / 建议下一步）

### 已融合
- 双目标同一 GUI，目标切换自动改默认库/默认库名/徽标/提示；
- MDF/LDF 双候选探测 + 已附加库识别 + 离线自动 ONLINE；
- 导入前备份、导入后常规校验 + 逐字段校验、结果表可导出；
- 线程安全日志队列（worker 不碰 tkinter）、busy 锁、失败可恢复；
- 清缓存提示（财贸 `BaseInfo` / 辉煌 `localData`）；
- 字典生成器统一输出“源字段 + 财贸目标 + 辉煌目标 + 规则 + 状态”。

### 建议下一步（未在本版实现，避免范围膨胀）
1. **预演 diff**：导入前只读比对“源行 vs 目标已有行”，输出将新增/将冲突/将跳过清单，先审后写。
2. **行级差异报告**：逐字段记录“源值/目标值/是否等价”，导出 Excel，便于客户签字。
3. **增量同步**：按源 `updatetime` 或自增 ID 水位，只导新增/变更；冲突行进入隔离表人工裁决。
4. **双向回传**：目标新增的单位/商品反写竞驰（需源端写入授权与编号策略，风险高，默认关闭）。
5. **批量多账套**：一次选择多个目标库，串行执行 + 汇总报告；每库独立备份/回滚点。
6. **凭据安全**：DPAPI 加密保存连接串，密码不落日志；当前仅环境变量，已满足交付底线。

## 六、结论

- 两条链路可以在**同一界面**下稳定运行，且都已用真实库写入 + 逐字段回读闭环。
- 财贸 225/225、辉煌 114/114 的字段级通过，说明字典不是“看起来对”，而是“写进去再读出来对”。
- 最大风险不在 SQL 语法，而在**编号体系、名称唯一性、单位/价格载体、开账状态**四处；这四处都已有针对性修复与验证记录。
- 下一版若只做一件事，优先做“预演 diff + 行级差异报告”，它能把交付前的信任成本降到最低。
