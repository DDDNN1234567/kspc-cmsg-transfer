# 竞驰管理通 → 管家婆双版本直导工具 V4.0 · 项目说明

> 面向对象：最终用户、实施工程师、后续维护者。
> 配套文档：`使用说明_V4.0.md`（操作步骤）、`功能日志_V4.0.md`（版本记录）、`软件功能实测记录_V4.0.md`（读取链路实测）、`数据字典_竞驰到双版本_V4.0.md`（字段级映射）、`项目设计经验总结_V4.0.md`（工程经验）。

## 一、项目定位

竞驰管理通（`kspcDefault`）是单库结构的中小进销存系统；管家婆有两条产品线：

- **财贸双全**：以 `Btype / ptype / Stock / Employee / Department` 等表承载基本信息，编号由目标自行生成，允许层级；
- **辉煌 TOP15**：基本信息同样分表，但写入必须走 `p_hh_BasicInsert*` 官方过程，过程会重排树编号、重算 `dsonnum/soncount/leveal`、登记权限串并刷新 `updatetag`。

本项目把两条原本独立的直导链路融合为**一个 GUI、一个源连接、双目标二选一**，并把“导入前备份、导入后核验、逐字段交叉验证、字典可追溯”做成固定流程。V4.0 是当前交付版，包含 V3.0 财贸直导、TOP15 适配器的全部有效功能，并排除了历史版本的已知缺陷。

合计：**10 个模块，7 个官方写入过程**（单位 B、商品 P、仓库 K、职员 E、部门 D、期初、价格追踪）。

### 3.2 工程功能

- **MDF/LDF 直接附加**：源与目标各一套；自动探测 `<库>_log.ldf` 与 `<库>.ldf`；已附加直接复用；离线库 `SET ONLINE`；缺日志 `ATTACH_REBUILD_LOG`。
- **导入前整库备份**：默认勾选，生成带时间戳 `.bak`；失败可回滚。
- **导入后核验**：财贸 32 项常规 + 225 项字段；辉煌 14 项常规 + 119 项字段。
- **字典页**：现场重生成“源字段 / 财贸目标 / 辉煌目标 / 规则 / 状态”，并标出未迁移原因。
- **结果页**：三元组 `(项目, 结果, 明细)`，可导出 CSV。
- **线程安全日志**：worker 不触碰 tkinter，队列 + 主线程 drain；busy 锁可解除。
- **清缓存提示**：财贸 `BaseInfo`、辉煌 `localData`，避免“库里有了、界面不显示”。
- **双目标卡片**：切换目标自动改默认实例/库/徽标/说明，减少误填。

## 四、关键数据规则

### 4.1 编号与树

- 辉煌编号必须**纯数字**；客户端用“编号前缀”还原父子，不读 `parid`。官方过程会自动生成合法树编号并返回 `g_tree/u_tree`，明细引用只能用返回值，不能自行推算。
- 财贸编号由引擎生成；父子为“父编号 + 5 位序号”，`leveal` 按层级写。
- 目标已有同编号或同名称时，辉煌过程返回 `rc=-1124`；适配器做“编号续排 + 名称 `(竞驰)` 后缀”双唯一化。

### 4.2 显示与刷新

- 辉煌写入后 `updatetag=10000`，并 `UPDATE xw_BaseUpdateTag SET UpdateTag=0 WHERE BaseType=...`；缺一不可。
- 财贸写入后同样登记刷新标记；客户端清缓存后重登。
- `deleted=0`、根节点保留、`pfullname/bname/efullname` 非空。

### 4.3 幂等

- 每个导入行在目标备注写入 `竞驰ID:n`（财贸 `竞驰导入|原编号:x|原ID:n`）。
- 重复执行时先按备注查重：命中则跳过，不再产生第二条；部门模块本轮实测曾因缺少幂等产生重复 `00002 业务部(竞驰)`，已清理并加防重。

### 4.4 库存口径

- 财贸：`t_prime_goodsstock` → 期初 `IniGoodsStocks`；`t_base_goodsstock` → 当前 `GoodsStocks + GoodsStockscost`。
- 辉煌：只有一套 `IniGoodsStocks`；源无单据时，把当前结存作为期初写入，保证迁移后当前库存一致。
- 因此“财贸期初 100 / 辉煌期初 90”是目标可承载口径不同，不是数据错误。

## 五、实测结果（真实库写入 + 官方读取链路）

### 5.1 财贸双全 `财贸测试demo`

- 常规校验 32/32；逐字段严格核对 **225/225，0 不符**。
- 官方 `xw_GetBasicData` 读取：B 7 行（6 条导入）、P 3 行（2 条）、K 7 行（4 条）、E 4 行（1 条）、D 3 行（1 条）、A 135 行（0 条，按设计）。
- 商品简称：源 `name` 为空，已回退全名；读取 `pname` 显示 `测试商品 / 测试123`。

### 5.2 辉煌 TOP15 `HH15testV4`

- 10 模块导入成功，`fail=0`；常规 14/14；逐字段 **119/119，0 不符**（含部门 5 项）。
- 官方读取：B 898 行（5 条导入）、P **24,738 行**（2 条）、K 24 行（4 条）、E 8 行（1 条）、D 3 行（1 条）、A 73 行（0 条，按设计）。
- 商品 `pname` 已按全名回填；部门 `00001 业务部` 由官方过程落库并在 `D` 读取中可见。

### 5.3 读取链路的关键参数

- 财贸：`DECLARE @o int; EXEC dbo.xw_GetBasicData ?,0,0,0,@o OUTPUT`。
- 辉煌：`EXEC dbo.xw_GetBasicData ?,0,'',0,0`；**5 参全普通实参，起止必须 `0,0`**。
- 辉煌此前的“商品/部门只回 1 行”，根因是把起止写成 `1,200000`；过程按起始行截取，不是权限过滤，也不是数据缺失。

## 六、运行与操作

```powershell
$env:KSPC_PWD = '<本机 sa 口令>'
python kpsc_unified_gui.py
```

或双击 `竞驰转管家婆双版本工具V4.0.exe`。口令只从环境变量读取；交付物、日志、GitHub 均无明文。

标准流程：

1. 源侧填实例/库，或选 `kspcDefault.mdf` → 附加并选中 → 测试连接。
2. 目标侧选“财贸双全”或“辉煌 TOP15”，填实例/库或选目标 MDF。
3. 预检：源表、目标表/官方过程齐全。
4. 勾选“导入前备份”，确认备份目录对 SQL Server 服务账户可写。
5. 一键直导 → 自动核验 → 查看汇总与逐项结果。
6. 按提示清缓存、重登客户端，在软件界面逐模块确认。

## 八、边界（按设计不迁移）

- 登录用户、权限、会话、操作日志、单据流水、自定义报表。
- 会计科目：源 `t_base_kmb` 50 行不迁移，目标账套自有科目。
- 客户价格追踪：源 `t_base_price` 为 0 行，按“无数据不写”。
- 地区：源 `t_base_area` 为 0 行，暂不建地区模块。
- 辉煌部门 `par_jl` 无对应语义，保留源库。
- 目标已有真实数据时，不提供“清空重导”作为默认操作；只做增量式追加并靠备注幂等。
