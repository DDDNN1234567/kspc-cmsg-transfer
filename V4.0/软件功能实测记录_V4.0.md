## 一、调用方式（两版本参数不同，不能互抄）

### 财贸双全

```sql
DECLARE @o int;
EXEC dbo.xw_GetBasicData ?, 0, 0, 0, @o OUTPUT;   -- @cMode, @nUpdateTag, @nUsePage, @Rec, @OutRecords OUTPUT
```

- 第 5 参必须 `OUTPUT`，且先 `DECLARE`。
- 模式：`B` 往来单位、`P` 商品、`K` 仓库、`E` 职员、`D` 部门、`A` 会计科目。

### 辉煌 TOP15

```sql
EXEC dbo.xw_GetBasicData ?, 0, '', 0, 0;   -- @cMode, @nUpdateTag, @EtypeID, @beginRec, @endRec
```

- **5 个参数全部是普通实参**；第 5 参传 `OUTPUT` 会报 8162。
- `@EtypeID` 传空串才取全量。
- **`@beginRec` 与 `@endRec` 必须都传 0 才是全量**。此前把起止写成 `1 / 200000`，过程按“起始行”截取，商品与部门都只返回 1 行；改成 `0, 0` 后商品返回 24,738 行、部门返回全部行。这是调用参数问题，不是数据缺失，也不是权限过滤。
- 权限串 `p_hh_GetRightStr` 另测：`OperatorID` 传 `'' / '00000' / '00010'` 三种，`@TableStr`、`@TableWhereStr` 全部返回空串，行数不变，排除权限过滤。

## 三、本轮实测暴露并已修正的三处问题

| 问题 | 真实原因 | 修正 | 复测结果 |
|---|---|---|---|
| 辉煌商品 P 只返回 1 行 | `@beginRec=1 / @endRec=200000` 被过程当作“起始行”截取 | 统一改 `0, 0` | P 返回 24,738 行，2 条导入商品可见 |
| 辉煌部门 D 只有根行 | 适配器 `MODULES` 原先没有“部门”，源 `t_base_department` 1 行从未落库 | 新增 `department` 模块，调用官方 `p_hh_BasicInsertD`；字典同步映射 10 个字段 | D 返回 3 行，`00001 业务部` 可见 |
| 财贸/辉煌导入商品简称为空 | 源 `t_base_goods_inner.name` 本身为空，只写 `name` 就落空 | 写入时 `name` 为空则回退 `fullname`；财贸/辉煌同步 | 官方读取 `pname` 显示 `测试商品 / 测试123` |

> 说明：源数据 `name` 为空、`fullname` 有值，这是源数据事实；回填简称属于展示层兼容，不改变 `fullname`。

## 四、库存口径实测

| 源表 | 行 | 数量/单价/金额 | 写入去向 | 读取/核对 |
|---|---:|---|---|---|
| `t_prime_goodsstock` | 1 | 100 / 1000 / 100000 | 财贸 `IniGoodsStocks` | 期初 100，核对通过 |
| `t_base_goodsstock` | 1 | 90 / 1000 / 90000 | 财贸 `GoodsStocks + GoodsStockscost`；辉煌 `IniGoodsStocks` | 财贸当前结存 90；辉煌按“源无单据时当前结存即期初”的口径写 90，均核对通过 |

- 两版本对“期初”的语义不同：财贸可以同时保留期初 100 与当前 90；辉煌只有一套 `IniGoodsStocks` 期初表，本工具选择写当前结存 90，使迁移后软件当前库存与源一致。
- 因此“财贸期初 100、辉煌期初 90”不是错误，而是两目标可承载口径不同；字典与验证记录均已写明。

## 五、结论

1. 财贸 B/P/K/E/D 五个可迁移基本信息模块，导入行在官方读取链路中 **100% 可见**；A 会计科目按设计保留目标体系。
2. 辉煌 B/P/K/E/D 五个模块同样 **100% 可见**；商品全量 24,738 行读取正常，部门已补齐。
3. 字段级：财贸 **225/225** 通过；辉煌 **119/119** 通过（含部门 5 项）。
4. 本记录只描述“读取链路可见性”，字段值级核对见 `核心字段映射真实核对_V4.0.csv`、`TOP15写入字段交叉验证_V4.0.csv`。
