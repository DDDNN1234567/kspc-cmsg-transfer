# 竞驰 → 管家婆双版本直导工具 · V8.1 版本升级说明

- 升级版本：`V8.1 官方口径补强版`
- 基线版本：`V8.0 完成版`
- 发布日期：2026-11-07
- 适用范围：财贸双全链路、辉煌 TOP15 链路、千业双向模块
- 升级性质：**字段语义纠错 + 官方口径补强 + 实测回归**，不新增数据库结构，不改变原有操作入口

## 一、为什么必须升级

V8.0 的界面和大部分流程可用，但商品保质期/序列号存在三处“看起来通过、实际落错列”的 P0 问题：

1. `ShelfLife ← bzDateNum` 只覆盖财贸桌面端，漏了线上/手机端 `UsefulLifeDay`；
2. `bBlockNo ← serialType` 把“管理批号”当成了“序列号”，财贸正确列是 `ManSerialNum`；
3. 辉煌侧 `p_hh_BascInsertP_Commodity` 的三个参数 `@LifeDay / @snManCode / @pjobmancode` 此前没有真正传入，且 `@snManCode` 必须传中文枚举，传 `'1'` 会被官方过程静默落 0。

V8.1 的目标不是“再加几个卡片”，而是把上述三项改对，并用真实库回读证明。

## 三、官方口径（升级后的唯一正确映射）

| 源字段 | 财贸目标 | 辉煌目标 | 说明 |
|---|---|---|---|
| `bzDateNum` | `ShelfLife` + `UsefulLifeDay` | `UsefulLifeDay` | 财贸双写；辉煌走 `@LifeDay` |
| `serialType` | `ManSerialNum`（0/1） | `SNManCode`（中文枚举→0/1/2） | `bBlockNo` 不再承接 |
| 无 | `bBlockNo=0` | 无 | 管理批号，不是序列号 |
| 无 | 无 | `PJobManCode=0` | 源无启用批次字段，统一写 `否` |

辉煌 `@snManCode` 映射：

- 空 / 0 → `不管理` → 落 0
- 2 → `仅实物仓库管理` → 落 2
- 其它非 0 → `管理序列号` → 落 1

**注意：传 `'1'` 不是“管理序列号”，会走官方过程的 `ELSE` 分支落 0。这是 V8.1 升级说明里最需要提醒实施人员的一条。**

## 四、升级步骤

### 4.1 升级前

1. 停止正在运行的旧版工具；
2. 对目标账套做一次完整备份（财贸用 SQL Server 备份，辉煌用账套备份）；
3. 确认源库 `kspcDefault.t_base_goods_inner` 可读、目标库连接正常；
4. 记录旧版 EXE 的 SHA256，便于回退。

### 4.2 替换

1. 用 `竞驰转管家婆双版本工具V8.1.exe` 替换旧 EXE；
2. 保留原 `文档\`、`源码\`、`融合_千业V3.1\` 目录结构；
3. 首次启动确认标题栏显示「V8.1 官方口径补强版」；
4. 进入「校验与差异」，确认预检显示「34 项常规 + 247 项严格 + 模板 35 项」。

### 4.3 回归

财贸链路：

1. 选择 `财贸测试demo`（或客户测试账套）；
2. 先「只读预检两侧结构」，确认无缺列/缺过程；
3. 一键直导，导入前自动备份；
4. 校验必须 34 项全通过，重点看四条字段项「不符 0 行」；
5. 回读一个商品，确认 `ShelfLife`、`UsefulLifeDay`、`bBlockNo=0`、`ManSerialNum` 四项符合源值。

辉煌链路：

1. 选择 `HH15testV4`（或客户测试账套）；
2. 确认官方过程 `p_hh_BascInsertP_Commodity` 存在；
3. 导入后回读 `UsefulLifeDay`、`SNManCode`、`PJobManCode`；
4. 若 `SNManCode` 仍为 0，先检查传入值是不是中文枚举，而不是 `'1'`。

### 4.4 回退

- 财贸：用导入前备份 `财贸测试demo_V81_20261107.bak` 恢复到独立库，确认无误后再切换；
- 辉煌：用账套备份回退；
- 程序：换回 V8.0 EXE 即可，V8.1 未改数据库结构，回退不需要改表。

## 六、兼容性说明

1. **财贸老库**：若 `ptype` 缺 `ManSerialNum` / `UsefulLifeDay` 等列，导入前会自动裁剪，不会整批失败；但缺列意味着该库版本较老，建议先升级管家婆客户端/账套。
2. **辉煌老库**：若官方过程参数不含 `@snManCode` / `@pjobmancode`，调用会报参数错误；此时应使用与账套版本匹配的官方过程，或退回 V8.0 的兼容路径。
3. **不影响**：单位、仓库、职员、部门、期初、结存、价格、千业双向、缓存清理、恢复回滚等既有功能。
4. **不改表结构**：V8.1 只写数据，不新增列、不改索引、不修改官方过程。

## 七、已知边界

- 财贸非零序列号分支未在真实源库出现（源 `serialType` 全 0）；该分支已在辉煌官方过程用合成值验证，财贸侧为同一 `serial` 变量。
- `SerialConfig` 官方语义未完全确认，暂不写，留 0。
- 竞驰源无“启用批次”字段，辉煌统一写 `否`。
- 官方错误码未全部前置到预检；`error6/15/20/21/25/28/29/30/31/37/38` 仍以过程返回为准。
- 本轮财贸只导入 2 个商品，未在 26,920 行辉煌库做全量商品导入。
